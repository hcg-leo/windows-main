# windows-main

Personal Windows setup for a Galaxy Book 3 360: app installs, config files, and small
batch scripts that set up a fresh Windows install. There is no build, no tests and
no package manager. The repo is just files plus scripts that copy them into place.

## Layout

| Path | What it is |
|---|---|
| `autounattend.xml` | Unattended Windows install answer file, generated by **Winhance** (~3600 lines). Prefer regenerating it in Winhance over hand-editing; if you must edit, make small, targeted changes. |
| `batch/` | One `.bat` per setup task. Run by hand after a fresh install. |
| `batch/apps.bat` | All app installs via `winget`. Add new apps here. |
| `ahk/wm.ahk` | AutoHotkey **v2** window-manager hotkeys (Win+Q close, Win+W maximize, Win+Enter terminal, Win+1..9 virtual desktops). |
| `altsnap/`, `helium/`, `powershell/`, `zed/` | Config files for those apps; deployed by the matching `batch/<app>.bat`. |
| `powershell/settings.json` | Actually the **Windows Terminal** settings file. |
| `zed/themes/nord.json` | Custom Nord theme for the Zed editor. |
| `startup/` | Shortcuts copied into the Windows Startup folder by `batch/startup.bat`. |
| `manga/`, `music/`, `books/` | Media folders. Only the downloader scripts are tracked; downloaded media is gitignored. |
| `shutup10/` | Placeholder for an O&O ShutUp10 config (only `.gitkeep` so far). |
| `*.png`, `*.jpg` | Wallpapers / profile picture. |

Folders like `drivers/`, `localsend/` and `prism/` are referenced by scripts but exist
only locally. They are intentionally untracked.

## How the batch scripts work

- Config deploy scripts use `robocopy <repo folder> <AppData folder>`.
  **`/MIR` deletes anything in the destination that isn't in the source.** Be careful
  when changing the flags or the destination path: `zed.bat`, `powershell.bat`,
  `startup.bat` and `localsend.bat` all use `/MIR`.
- Settings-page scripts just run `start ms-settings:<page>`.
- Paths are **hardcoded absolute paths** to `C:\Users\Aran Thananjayan\Desktop\windows-main\...`,
  so the repo is expected to live at `Desktop\windows-main`. Keep new scripts consistent
  with that, and quote every path (the username has a space in it).
- Style: start with `@echo off`, keep scripts short and single-purpose, use
  `set /p` for prompts and `pause` when the user needs to read output.
- Don't run scripts that change the system (installs, robocopy, registry, rename,
  mklink, driver installs) without asking first. Reading or editing them is fine.

## .gitignore: whitelist model

There is a single root `.gitignore`. **Never create `.gitignore` files in subfolders.**

- `/*` ignores everything at the top level by default.
- `!/folder/` tracks a whole folder (used for config folders).
- Media folders use `/folder/*` plus `!/folder/file` lines, so only listed files are tracked.

When adding a new top-level file or folder that should be tracked, add a `!` line for it,
otherwise git will silently ignore it. Check with `git status --ignored`.

## README

`README.md` contains a file tree of tracked files. When tracked files are added, removed
or renamed, update that tree to match `git ls-files`.
